# 统一机器地址显示与 SOCKS5 验证

## 已确认的问题

0.2.21 仅在 `command_show` 解析当前入口地址。新增与换端口的预览、首次安装后的输出、修改出口及重置后的显示未接入解析。列表里的本机直连出口仍显示历史记录。对照实验确认，仅改变保存的入口地址不会改变 SOCKS5 验证请求；实际 VPS 的验证失败原因尚待现场诊断。

## 实现边界

- 所有用户可见链接与二维码统一使用一次展示期间检测确认的入口地址；沿用域名、固定地址退出及不确定网络的保护。
- 本机直连出口独立读取实时公网 IPv4，批量展示复用同一次检测；失败显示未验证，不把历史值当作当前值。
- 保留纯链接生成器用于兼容性比对。状态、配置、备注、凭据、端口、SOCKS5 地址与出口记录均不因查看而改写。运行时继续监听所有 IPv4。
- SOCKS5 验证使用三个检测站依次回退，忽略默认 curl 配置和代理绕过环境。只接受请求成功且内容为有效 IPv4 的响应。失败只显示安全的错误分类与数字代码，不输出凭据或原始错误。
- 状态检测已读取实际出口，其明确标记的历史记录继续保留；普通升级不变量和回滚机制不变。

## 实施及验证

1. 在旧版本复现新增显示错误，扩展地址显示测试并验证旧版失败。
2. 统一展示上下文，覆盖单条、批量、预览、列表与直连显示。
3. 独立验证 SOCKS5 失败回退、失败响应正文、环境隔离与错误脱敏，再修改验证函数。
4. 执行地址、SOCKS5、集成、预览、端口、自动更新、回滚和静态测试，保留源码哈希、时间、结果及清理记录。
5. 检查补丁与兼容性；发布需要单独记录 GitHub 和下载版本结果，不能将本地测试说成客户网络已恢复。
